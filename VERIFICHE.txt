CORREZIONE DELLA STORIA 1.2.0

Le nuove importazioni seguono la storia della directory scelta attraverso
copie e spostamenti, usando l'URL alla revisione massima come peg revision.
La selezione non si ferma più all'ultima copia del ramo (--stop-on-copy).
La prima revisione viene calcolata dal log e non è fissata a un valore predefinito.
L'interfaccia distingue l'origine della storia dalla creazione del ramo corrente.

Il motore SVN CLI + Git è predefinito su Windows, Linux, macOS e WSL.
Le nuove importazioni non richiedono git-svn. Il codice del motore precedente
rimane per compatibilità delle API, verifiche e uso esplicito di dati precedenti.
Il riferimento git-svn-id usa l'URL storico corretto per ogni revisione.

L'ambito history_scope=lineage identifica una cartella di lavoro distinta
rispetto alle importazioni parziali 1.1.x; le vecchie cartelle restano disponibili.
La pubblicazione continua a rifiutare un branch remoto con commit diversi.

PREPARAZIONE REPOSITORY PUBBLICO

I sorgenti separati, il file unico, lo script di assemblaggio e la documentazione
sono mantenuti alla versione 1.2.0. Gli esempi usano nomi e revisioni generici.
README.md descrive l'avvio, i quattro campi e la posizione dei dati locali.
Il file .gitignore esclude configurazione e stato delle migrazioni, log,
cache Python, ambienti virtuali, archivi ZIP di build e file locali degli IDE.
Il file unico svn_git_migrator.py rimane tracciabile; non è prevista un'esclusione
generica dei file JSON. Nessuna licenza o attribuzione è assegnata automaticamente.
Queste modifiche alla distribuzione non introducono nuovi risultati di test:
gli esiti della versione 1.2.0 sono riportati nella sezione seguente.

BASELINE DEL MOTORE GIT-SVN

Nella versione iniziale sono stati eseguiti sette test automatici, tutti passati senza skip, con repository SVN e Git locali
reali e indipendenti da account o server esterni.

Ambiente del backend: Linux, Subversion/svnadmin 1.14.5, git-svn 2.47.3.

Casi coperti:
- Intervallo di revisioni e selezione del solo branch.
- Snapshot iniziale completo da una copia del trunk.
- Copia di sottodirectory da un percorso escluso dalla storia.
- Confronto del tree Git con svn export alla revisione massima.
- Conservazione degli username, delle date (precisione Git al secondo), dei
  messaggi di commit e del riferimento git-svn-id.
- File binari, contenuti e nomi Unicode, link simbolici, rinomine e cancellazioni.
- Revisioni con sole proprietà SVN e creazione di directory vuote: commit
  presenti nella cronologia; le directory vuote non sono rappresentate nel tree.
- Interruzione al primo commit importato, poi ripresa con una nuova istanza.
- Riesecuzione idempotente.
- Nessun push durante l'importazione locale.
- Pubblicazione esplicita su un Git bare locale e verifica del riferimento.
- Seconda pubblicazione idempotente.
- Rifiuto di un branch remoto con storia diversa e verifica del suo SHA inalterato.
- Pianificazione di revisioni molto distanti senza enumerare i numeri intermedi.

Interfaccia grafica avviata e ispezionata su un desktop Linux reale:
verificati i quattro campi, l'impaginazione, gli stati iniziali dei pulsanti e
il rifiuto dei campi vuoti. Validazione sintattica dei sorgenti e del file unico.

LIMITI DELLA VERIFICA

Non è stata cronometrata un'importazione con milioni di revisioni o su una rete
aziendale. Le prove usano repository locali generati per i test.
Il launcher AVVIA_WINDOWS.cmd avvia Python nativo Windows. La versione 1.2.0
usa Git e SVN a riga di comando su tutte le piattaforme, senza richiedere git-svn
per le nuove importazioni.
Il launcher e l'esecuzione nativa Windows/macOS non sono stati eseguiti su quei
sistemi: la disponibilità dei client e il riuso delle credenziali
devono essere verificati nell'ambiente di esecuzione. L'interfaccia della versione
iniziale è stata verificata su Linux. Il launcher WSL rimane una modalità
alternativa e separata.

AMBITO DELLA STORIA

La storia della 1.2.0 comprende gli antenati della directory SVN selezionata,
anche attraverso copie e spostamenti di una directory che la contiene.
Le revisioni estranee alla storia restano escluse. Una copia eredita il sorgente
solo fino alla propria copyfrom-rev, non le sue modifiche successive.

Non viene ricostruito il grafo dei merge, né viene aggiunta tutta la storia
precedente di ogni singolo file o sottodirectory copiati successivamente dentro
la directory selezionata. I contenuti di svn:externals restano esclusi.
Le email login@UUID sono identificativi tecnici. Il client deve poter leggere
la storia e i contenuti necessari con le credenziali configurate.

I test storici 1.1.x descritti sopra usavano l'ambito limitato all'ultima copia
del percorso. Sono conservati come baseline del motore e dei controlli di
integrità; la selezione degli antenati è una funzione nuova della 1.2.0.
